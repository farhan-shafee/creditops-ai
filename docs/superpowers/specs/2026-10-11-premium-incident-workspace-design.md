## Purpose and inspected baseline

Help a technical hiring manager understand a synthetic trading incident, inspect the returned evidence, compare the model proposal with recorded rule output, and prepare a useful human-review handoff in five minutes. Keep CreditOps' dark navy, teal and amber identity; improve reading order, text size, spacing and interaction rather than adding decoration or a new incident-management platform.

## Workspace and user journey

Use **Overview | Evidence | Review | Handoff** as local tabs inside the selected recorded incident, not additional sidebar navigation or new routes. Enable this presentation for matching replay investigations with showcase provenance. Other modes retain their existing interface.

The header always identifies the incident and shows **Synthetic · Recorded · Human review required**, observed business impact, the recorded supported failure condition and whether an initiating cause is confirmed. Never replace an absent condition with a fixture answer. Keep returned-sample coverage and evidence cutoff visibly separate; put original model, generation time, source provenance and uncalibrated scores in expandable technical details. Label playback status separately from the original recording's outcome.

1. **Overview:** read a concise event-derived impact summary, affected RFQ/order journeys, the recorded advisory condition and material unknowns. Expand diagnostic activity to inspect application-selected checks, model decisions, assessment and validation with existing attribution. Playback executes none of those original calls.
2. **Evidence:** choose a service/metric, align its samples with logs and business events, select an RFQ/order journey, and open a source object. Pin useful returned evidence without altering it.
3. **Review:** compare original proposal and recorded advisory output by field, inspect recorded rule reasons and existing project review notes, and add a personal note. Original JSON remains an optional secondary view.
4. **Handoff:** choose technical or stakeholder template, inspect the deterministic draft, then copy Markdown or print for browser Save as PDF. No sending, AI generation or operational approval occurs.

Desktop: a compact sticky incident header below the existing topbar; a single section tab row; two columns for Overview summary/impact and Evidence controls/journey beside the timeline. Review has a three-column comparison. Use comfortable 14–16px body text, at least 1.5 line-height, bounded prose width and 16–24px spacing. Scores and JSON do not lead the page.

At 768px and below: stack sections, use a wrapping four-tab row rather than a second menu, and turn comparison rows into cards with the two labeled values and recorded reasons. At 390px and 320px, controls and source IDs wrap; only the accessible sample table may scroll horizontally. The existing drawer becomes full-width. Keep the compact incident identity/labels visible without a sticky block consuming most of the viewport.

Tabs use `tablist`/`tab`/`tabpanel`, roving focus, arrow/Home/End navigation and explicit Enter/Space activation. Preserve existing focus outlines, skip link, modal Escape/focus restoration and reduced-motion behavior. Every visual point has a keyboard-accessible table equivalent. Section changes keep focus on the selected tab; opening/closing evidence returns focus to its trigger. No hover-only information.

## Recording-owned data contract

Derive a read-only view from the active `Investigation`, never console `metrics`, current `Incident.timeline`, the live business-impact endpoint, another investigation or another session. Require the investigation's `incident_id` to match selection and its recorded incident evidence's `data.incident_id`. Preserve the existing replay artifact loader/hash checks; do not add a new loader or endpoint.

| Purpose | Existing fields and derivation |
|---|---|
| Exact sources | `evidence[]`: `id`, `kind`, `service`, `timestamp`, `summary`, `data`. Index only top-level returned rows, scoped to this recording. |
| Metrics | `kind === 'metric'`, `data.metric`, finite numeric `data.value`, `data.unit`; group by service + metric + unit. Keep evidence ID and actual timestamp for every sample, including standalone and `sample_kind: 'series'` rows. |
| Logs | `kind === 'log'`; summary/message, severity and explicit `data.rfq_id`, `order_id`, `trace_id` when present. Render inert text. |
| Business journeys | `kind === 'business_event'`; literal `data.rfq_id`, event type, quote/order/economic-order identifiers and trace IDs. Reuse recorded event grouping and unique-RFQ event counts from `business-impact.tsx`. |
| Context | Returned incident `data.timeline` and topology `data.services`/`dependencies`. Topology services are strings, not the richer live `Service[]` objects. Context annotations are not extra returned sources. |
| Review | `provider_proposal`, `validation_outcome.changed_fields/rejected_fields`, `assessment`, `provenance.showcase.review_notes`; optional `provenance.playback_validation` remains a separate current check. |
| Time/provenance | `showcase.sample_start/sample_end`, `snapshot_cutoff`, `showcase.generated_at/exported_at`, original provider/model, steps' `selected_by`; playback `created_at` is not original generation time. |

The three packaged records contain 67/71/65 returned sources, including 50 metrics each. Arrays are not chronologically ordered. `TOPOLOGY-001` is reused across recordings, so an evidence ID alone is not a global identity. Nested context timelines cite unreturned IDs, including a deployment mentioned in the database example. Label these “Referenced in context; source not returned”; do not fetch, plot, pin or count them as returned evidence.

Use pure adapters and lightweight type guards for needed per-kind fields. Preserve unknown/raw fields in source inspection without promoting them to typed claims. Invalid timestamps/nonfinite values remain inspectable with a visible “Cannot plot this recorded row” warning; never create a timestamp, round fractional counts to integers, or convert connection samples into booleans. Empty lanes mean no returned matching observations, not healthy telemetry. Duplicate top-level IDs or incident mismatch block specialized rendering/export because source identity is ambiguous. A malformed/missing recording shows an explicit error and leaves selection available; never fall back to a different record or current simulation. Missing proposal, validation or assessment each gets its own unavailable state.

## Linked evidence timeline

The default axis spans actual timed metric/log/business observations; show the full UTC date at its boundaries. Compute and label actual lane coverage and gaps. Show metadata coverage separately if it differs. Display the later collection cutoff as a separate fact, not a last metric value, health claim or an extra sample stretching the chart. Context annotations outside sample coverage remain in a timestamped list.

Plot discrete sample markers at actual timestamp distances, with original numeric values and units. No filled area, interpolation, smoothing, inferred points, trend badges or continuous-health bands. Derive a numeric y-domain that contains every finite value, including negative/constant values. Keep separate series for different units. Same-time observations remain separate rows; different values remain distinct markers. Overlapping markers open a list of their exact sources rather than selecting an arbitrary winner or averaging. Sort a copied view by parsed timestamp, then stable evidence ID; never reorder or mutate the source array.

Use native service/metric selectors and bounded UTC start/end inputs; default to all services and the first available service/metric/unit combination in lexical order, without diagnosis-specific defaults. Validate range order and bounds visibly. Service selection filters metric/log lanes; metric selection affects only metrics, since logs do not contain a metric field. The business lane retains its explicit request selection. Choosing a time window affects displayed evidence only. Prominently state “Recorded assessment unchanged; filters do not rerun investigation.” Reset filters restores the full sample window, all services and all requests; it retains pins, notes and selected source.

Clicking a marker, timeline event or table citation selects its source and opens the existing drawer. A time selection highlights all observations at that instant without implying a causal relationship. Changing filters preserves the selected source; if hidden by filters, the drawer says so and offers Reveal source to adjust the relevant filters explicitly. Review/pin citations can open off-filter evidence without silently changing filters. Closing the drawer retains a selected-source highlight. Switching recordings clears selection and closes the drawer through the existing console lifecycle guards.

An RFQ selector uses literal returned business-event identities; order choices use recorded economic-order identity, preserving retransmission of the same order. It narrows business events and highlights only logs with an exact RFQ/order/trace relationship. Existing log RFQ identifiers can differ from business RFQ identifiers; do not infer a match from prefixes, service membership, temporal proximity or topology. Service metrics remain service-level and show “Not attributed to this RFQ” unless explicit returned request/trace fields support that relationship. Missing links are useful unknowns.

Reuse exact decimal-string formatting for requested par and quote price; never perform floating-point money arithmetic. Preserve quote expiry versus RFQ expiry, pending/unknown ACK and same-order retransmission distinctions. No event counts become fills, executions, settlement, financial loss or revenue impact.

## Readable review and personal notes

The comparison columns are **Field | Original model proposal | Recorded advisory output**. Include summary/domain/supported condition; observations and supporting IDs; confirmed cause and candidate triggers; unknowns/limitations; alternatives; recommendations/RCA; and model support versus rule support, both explicitly uncalibrated. Render original and final values verbatim in readable lists. Compare arrays as collections rather than inventing sentence-to-sentence correspondences after normalization. Missing, null and empty values remain distinct.

Attach rule labels only from recorded change/rejection entries: field path, stage and concise recorded reason. A generic `known_domain_rule_normalization` reason remains generic. Multiple entries for one path retain their stages; any field count counts unique paths and is labeled normalization count, not detected-error count. Unknown paths remain visible in an “Other recorded changes” list.

Keep project notes' `identified`, `overstatements`, `validator_changes` and `unknowns` intact. Present narrative overstatements as specifically identified project-review findings, separate from rule changes; do not assign free-form notes to fields using guessed keyword matching. State that other model-written claims were not independently verified. Valid references establish returned identity/type, not the truth of surrounding prose. Missing-source tokens stay non-inspectable instead of becoming invented citations. Original, recorded validation/final JSON and separately labeled playback validation remain expandable; no edited proposal or new rule result replaces recorded text.

Personal notes consist of one plain-text note (maximum 4,000 characters) and up to 20 pinned returned IDs per recording. Label them **Personal, unverified notes — this tab only; not team approval**. Use `sessionStorage`, not existing `localStorage` wrappers or a server. Scope a versioned key by existing `sessionId()` + incident ID + `showcase.source_sha256` + `showcase.exported_at`; do not use the fresh playback UUID. Validate stored shape, limits and pin membership before use. These stable public source fields are present in all three recordings; absent identity disables durable notes with an explicit message rather than sharing a generic key.

Refresh restores notes/pins for the same demo session and recording version while resetting section/filters to Overview/full snapshot. Recording changes reset view state and restore only that record's notes. A new session/version gets no prior notes; separate tabs do not synchronize edits. If storage is denied/full, retain in-memory state and show “Notes cannot survive refresh”; invalid saved data produces a visible reset option without substituting another key. Normal tab closure ends persistence, subject to browser session restoration. Never change existing session/auth behavior.

Reset filters preserves personal state. Successful existing Reset Scenario clears only workspace notes/pins for that reset incident in this tab/demo session, with this effect stated beside the control; failed reset preserves them. Explicit Clear personal notes removes only the current record's entry. Notes are escaped plain text, never parsed as Markdown/HTML, supplied to a model, added to evidence, treated as approval or automatically included in exports.

## Deterministic handoff

Prepare handoff creates an inspectable draft from the full matching recording, independent of current timeline/RFQ filters. State that scope above the draft. Optionally include a clearly labeled pinned-source appendix; pins highlight sources without narrowing the impact/uncertainty summary. Do not add filtered incident briefs in the first implementation. Personal notes remain a separate workspace panel and are excluded from copy/print.

Technical template: incident identity and recorded scope; event-derived observed symptoms/affected requests; actual UTC observation timestamps; recorded supported condition; returned sources; recorded unknowns/limitations, project-review cautions and advisory next checks. Recommendations remain proposed checks, never completed actions. Copy recorded causal wording only with its qualification; use null `confirmed_cause` as “Initiating cause unconfirmed,” not the model's stronger original prose.

Stakeholder template: a short event-derived impact paragraph, advisory condition explicitly qualified, unresolved outcome/cause, and a plain-language request for human review. Put complete material limitations and source references in a labeled appendix instead of hiding them to shorten the paragraph. Do not generate a new paraphrase of model prose or expose internal implementation details as business impact.

Both templates carry **Synthetic · Recorded · Draft · Human review required**. Distinguish observation time, original generation time, packaged export time and this draft's preparation time. Capture preparation time once per draft so preview, Markdown and print agree. Re-preparing changes only the local draft timestamp/content, not investigation state. Include a source appendix with each cited top-level ID, kind/service, timestamp and relevant recorded value or event/message. In-app references use the exact drawer; copied/printed references resolve by ID to appendix entries without session-bearing URLs. Use an explicit export allowlist; omit session capability/header values, playback IDs, raw receipt/configuration/usage objects, credentials and machine paths. Use already sanitized public evidence; do not export arbitrary `data` fields or raw JSON. Unknown/nonreturned references are explicitly unavailable, never silently repaired.

Copy uses `navigator.clipboard.writeText` with success/error feedback; on denial show selectable Markdown for manual copy. Browser Print invokes a print-friendly draft region with white background, readable black text, intact headings/source lists and sensible page breaks. Print excludes sidebar, tabs, controls, notes and unrelated/raw panels. Browser Save as PDF is the only PDF path. No new request, backend endpoint, upload, sender, external integration or approval/sign-off mechanism.
