# SSE polling read ownership

Only database reads made by the investigation SSE polling iterator use this owner. Endpoint authorization/session lookup, recorded execution, event payloads/order and the existing stream deadline remain unchanged. Direct API reads keep their existing cleanup policy.

Each application instance has four slots shared by active reads and retained cleanup. This conservative budget leaves the default five-plus-ten connection pool unchanged. Reserve before creating a child task; the initial reservation is made after authorization and before response headers. An unused reservation is released by the response finally even when header sending is cancelled. Capacity exhaustion returns503 before headers, or the existing safe `event: error` framing followed by closure after a stream starts. No queue, retry or child is created when admission is unavailable.

A native asyncio child owns each polling database read. On outer cancellation, the owner explicitly cancels an active read once and preserves the original outer CancelledError. Polling session/driver release marks its phase synchronously before awaiting public close. A direct Task.cancel bypasses AnyIO shielding, so a child already releasing resources is joined without sending a new cancellation. Transient driver-release phases are balanced; a later resumed read remains cancellable. The same child and resource receipt own both work and release; no second task registry is created. A cleanup-only shield protects a non-cancelling wait of at most two seconds. Expiry reports `sse_cleanup_deadline`, releases the request, and retains the exact child, resource receipts and capacity slot. The two-second bound applies to request waiting, not physical driver completion.

Polling sessions and the single public invalidation handoff await session/raw-driver close directly. Acquired-query cancellation and pre-ping cancellation use the same handoff; the pre-ping child can own a physical connection before a checkout event exists. Successful resource acknowledgements plus an observed task result release capacity. A close failure reports `sse_cleanup_failed`; its resource and capacity remain retained even if SQLAlchemy later attempts dialect termination. A completed task alone is insufficient acknowledgement. No logger suppression, driver patch or forced second cancellation is used.

Shutdown stops admission first, preserves the existing investigation-worker shutdown behavior, and gives polling cleanup a five-second join grace without cancelling pending children again. Uvicorn's installed default graceful-shutdown setting isNone; no hosting setting is changed. Incomplete ownership reports `sse_shutdown_incomplete`, raises a lifespan shutdown failure, keeps ownership records, and skips engine disposal. An operator or supervisor may be required if native work never returns. Process/asyncio Runner termination is external containment, not a promise made by this owner.

Ordinary `sse_read_failed`, cleanup deadline/failure, shutdown-incomplete, termination errors, pool timeouts and realHTTP5xx remain fatal acceptance failures. Focused injected failures exercise those receipts and do not excuse normal failures. The prior held-native proof and its failed hard-joined deadline assertion are immutable historical evidence. This approved contract changes the current request-return expectation by retaining service ownership; it does not preempt a blocked Python UDF or guarantee eventual joining.
